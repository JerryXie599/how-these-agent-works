# 反夸大、记忆与报告

这一页讲平台如何把"模型上报的发现"变成可信的交付物，共三部分：二次验证与评级（对单个发现）、记忆蒸馏（跨任务的经验）、报告生成（最终交付物）。

## 二次验证与独立评级

每个漏洞记录（finding）上有两个互相独立的状态字段：

| 字段 | 含义 |
| --- | --- |
| `secondary_verified` | 是否被一个专职复核会话**独立重新验证过**（不是上报者自己说的） |
| `redteam_rating` | 红队视角的可利用性评级，四级量表（严重 / 高危 / 中危 / 低危），与入库时的严重度互相独立 |

评级必须附带不少于 40 字的理由；量表禁止跳级（不能因为"看起来严重"直接标严重级——严重级要求证据已证明实际利用成功）。`info` 不是第五级，只用于复核未通过时的收口。

**入库门闩**（`graph/model.py:398`）规定了几种情况的合法性：

- 首次上报，两个字段都不填 → 放行（进入待复核状态）；
- 只填二次验证、或只填评级 → 必须附 40 字以上理由；
- 只写理由但两个字段都没填 → 直接拒绝上报。

**复核是独立的旁路作业**（`review/jobs.py`）：由专职的复核 Pi 会话重新执行验证，不阻塞主任务；同一条发现的验证与评级不会并行重复跑；同一簇（同 CVE 或同利用位置）的发现复核过一次即整簇覆盖。复核一旦完成，即使证据层仍判定 pending，状态也直接升为 verified——二次验证本身就是真实性结论。

**报告门槛**让这套流程有约束力（`api/routes.py`）：单洞详情页与正式漏洞页只在 `secondary_verified` 为真时生成；未复核的发现前端显示占位说明，不用类别模板填充。高危/严重漏洞缺少已验证 PoC 时，报告拒绝合成脚本，只写"无人工复现 PoC"。

## 记忆库：跨任务的经验

记忆存在 SQLite 的 `memory` 表，分两级：

| 级别 | 范围 | 写入方式 |
| --- | --- | --- |
| episode | 单个项目（按目标指纹关联） | 追加，永不覆盖 |
| lesson | 全局（CTF 与红队赛道共用） | 按 key 合并：合并触发条件/做法/避坑，累加胜负计数，版本号递增 |

**准入**：不是所有结果都值得沉淀。`memory/evolve.py` 的规则——结局为夺旗成功、或产出高危/严重级发现（且经二次验证或带评级）的执行，才进入蒸馏；失败局、中低危、空跑一律不记。

**蒸馏两步**：

1. 机械抽取：从执行记录里抽出"什么时候适用（目标栈与线索）、该做什么、该避免什么、成功路径"，并按胜负计数计算置信度（多次使用却从未成功的手法会被降权）。
2. 模型精炼：用一次性无工具 Pi 会话改写成标准格式，提示词明确禁止记录：IP、主机、端口、题号、URL、flag 原文、具体 payload、工具名罗列——只保留手法顺序与思路，保证换一个目标仍然适用。模型失败就回退用机械草稿。

**回灌与防背题**：下一局每轮检索最多 6 条相关经验注入简报（同时计入御主的简报）。为防止经验变成"背题答案"，有三道检查：本项目自己的记录不回灌给自己；经验的"该做什么"必须能与当前图上已有的信号衔接（不能凭空多出一步）；相关性打分无保底分，没有交集就是 0 分。注入文案本身注明"禁止当作本题步骤清单"。

## 报告生成

交付报告的生成链路（`report/` 模块）：

```text
1. build_report_data（generator.py:268）
   聚合：全部发现（按赛道可见性过滤）+ 图上未入库的漏洞节点 + PoC + 最优路径 + 资产
2. 压缩为事实包（claude_export.py）
   最多 24 条发现、字段截断、按 slot_id 编号
3. 一次性无工具 Pi 会话改写（role=report-export，最多尝试 2 次）
   只输出槽位 JSON：禁止输出 HTML、禁止改版式、禁止编造 URL/CVE
4. assemble_deliverable（slots.py:800）
   校验 JSON，填入预置 HTML 母版的 14 个槽位（封面/摘要/KPI/攻击路径/资产表/按严重度分组的漏洞）
5. 输出 HTML，Chromium headless 打印 PDF（失败回退 WeasyPrint）
```

单洞漏洞页（`pi_finding_page.py`）是另一条独立链路：输入单个发现的事实包，输出五段文字（摘要/影响/评级/复现/修复）写入数据库，门槛同样是 `secondary_verified`。

为什么改写环节用"无工具的一次性会话"：不共享猎洞会话的任何状态；没有工具就不能再次取证，杜绝编造细节；输出被限制为固定 JSON 结构，版式由代码控制；JSON 无效时任务报错或留占位，不用模板话术兜底。

## 与其他 Agent 的对照

| 话题 | Pi | Claude Code | DSH | AtkBrain |
| --- | --- | --- | --- | --- |
| 长任务记忆 | 会话摘要 entry | auto memory | 两层压缩 | 每轮重建会话，经验走记忆库 |
| 跨任务记忆 | 无 | auto memory | 无 | 两级记忆 + 防背题回灌 |
| 产出可信化 | tool result 协议 | 权限 + 审计 | 审批事件 | 二次验证 + 独立评级 + 报告门槛 |
